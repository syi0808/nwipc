# NWIPC 상위 아키텍처 설계서

## Cross-Platform Shared-Memory IPC for System WebViews

* **프로젝트명:** NWIPC
* **문서 상태:** High-Level Architecture Draft
* **첫 번째 플랫폼:** macOS
* **첫 번째 WebView:** WKWebView
* **Core language:** Rust
* **Renderer client:** TypeScript
* **macOS renderer module:** WebKit Injected Bundle
* **초기 데이터 플레인:** Shared-memory record ring
* **초기 macOS memory provider:** IOSurface
* **초기 macOS signal provider:** Darwin Notify
* **라이선스:** MIT OR Apache-2.0

---

# 1. 프로젝트 정의

NWIPC는 시스템 WebView renderer와 외부 native process 사이에 shared-memory 기반 binary IPC channel을 제공하는 독립 라이브러리다.

```
System WebView renderer
          ⇅
bounded shared-memory channel
          ⇅
External native peer process
```

NWIPC는 WebView host application을 payload 경로에서 제거하고 다음 기능을 공통으로 제공한다.

* 양방향 binary messaging
* FIFO ordering
* message boundary 보존
* bounded backpressure
* crash-safe publication
* session generation 격리
* reload 및 renderer process 교체 대응
* native peer lifecycle 처리
* 플랫폼별 memory attachment
* 플랫폼별 notification
* framework-independent API
* Wry 및 Tauri 선택적 adapter

# 3. 설계 원칙

## 3.1 Protocol ownership

NWIPC는 자신의 memory layout과 wire protocol을 직접 소유한다.

다음 외부 타입을 shared-memory layout에 직접 포함하지 않는다.

* iceoryx2 내부 구조체
* Rust `usize`
* Rust enum representation
* platform SDK struct
* pthread synchronization object
* C++ class
* Objective-C object pointer
* raw process-local pointer

Protocol field는 고정 크기 integer와 byte array로만 정의한다.

---

## 3.2 Provider abstraction

Shared memory와 notification은 provider interface 뒤에 숨긴다.

```
Protocol core
    ↓
Memory abstraction
    ↓
IOSurface / Mach / memfd / WebView2 SharedBuffer

Protocol core
    ↓
Signal abstraction
    ↓
Darwin Notify / Mach port / eventfd / host doorbell
```

---

## 3.3 Unsafe isolation

`unsafe`는 다음 low-level crate에만 허용한다.

```
nwipc-atomic
nwipc-memory-*
nwipc-signal-*
nwipc-renderer-jsc
nwipc-macos-spi
nwipc-macos-bundle-shim
```

상위 crate는 safe Rust API만 사용한다.

---

## 3.4 Fail closed

다음 상황에서 성능이 낮은 동작으로 암묵적으로 전환하지 않는다.

* protocol mismatch
* generation mismatch
* malformed cursor
* malformed record
* missing WebKit SPI
* renderer binding 실패
* unsupported memory provider
* signal registration 실패
* authentication 실패

대신 명시적인 capability와 structured error를 반환한다.

Fallback 결정은 application 또는 adapter 계층이 담당한다.

---

## 3.5 Generation replacement

Crash나 reload 이후 기존 shared region을 복구하거나 재사용하지 않는다.

```
Generation N invalidated
        ↓
all endpoints closed
        ↓
regions destroyed
        ↓
Generation N + 1 created
```

이 정책으로 allocator recovery와 partially corrupted arena 복구 문제를 제거한다.

# 31. 최종 module boundary

NWIPC는 크게 여섯 개의 독립 시스템으로 구성된다.

```
1. Protocol system
   Layout, records, validation, handshake

2. Data-plane system
   Ring, fragmentation, flow control, channel

3. Resource system
   Shared memory and signal providers

4. Lifecycle system
   Session, generation, bootstrap, supervision

5. Renderer system
   JavaScript engine binding and WebView runtime

6. Integration system
   macOS host, Wry, Tauri
```

각 시스템은 자신의 failure mode와 테스트 suite를 소유한다.
Bun은 이 저장소의 adapter system이 아니라 Bun source 내부 integration으로 관리한다.

# 32. 최종 책임 정의

## Protocol core

> 플랫폼과 프로세스에 독립적인 shared-memory layout과 binary messaging semantics를 정의한다.

## Data plane

> bounded SPSC channel, crash-safe publication, message boundaries 및 backpressure를 구현한다.

## Resource providers

> 각 플랫폼의 shared-memory object와 notification primitive를 생성하고 endpoint에 연결한다.

## Runtime

> session generation, bootstrap, endpoint lifecycle 및 resource cleanup을 조정한다.

## Renderer runtime

> WebView renderer의 JavaScript context에 안전한 message port를 설치하고 shared-memory channel을 구동한다.

## macOS host

> WKWebView 생성 전에 Injected Bundle과 renderer bootstrap을 구성하고 WebContent lifecycle을 관찰한다.

## Framework adapters

> NWIPC runtime을 특정 application framework의 WebView 생성 과정에 연결하지만 payload를 처리하지 않는다.

# 33. 아키텍처 완료 조건

상위 아키텍처는 다음 조건을 만족해야 한다.

1. Protocol crate가 macOS dependency 없이 compile된다.
2. Ring crate가 WebView 없이 테스트된다.
3. IOSurface provider가 protocol 없이 테스트된다.
4. Darwin signal provider가 shared memory 없이 테스트된다.
5. Renderer core가 JavaScriptCore 없이 테스트된다.
6. JSC binding이 WebKit lifecycle 없이 테스트된다.
7. Injected Bundle이 ring implementation을 직접 알지 않는다.
8. Host backend가 payload bytes에 접근하지 않는다.
9. Wry/Tauri를 제거해도 AppKit example이 동작한다.
10. Peer library가 WebView dependency 없이 사용된다.
11. Platform provider를 교체해도 protocol version이 바뀌지 않는다.
12. iceoryx2 crate 변경이 NWIPC protocol에 영향을 주지 않는다.
13. 각 unsafe crate의 audit surface가 독립적으로 측정된다.
14. 각 crate를 별도 owner가 병렬 개발할 수 있다.
15. backend failure가 fallback 가능한 structured error로 표현된다.

# 34. 최종 구조 요약

```
                             nwipc
                               │
                   ┌───────────▼───────────┐
                   │       runtime         │
                   │ session / bootstrap   │
                   └───────┬───────┬───────┘
                           │       │
              ┌────────────▼─┐   ┌─▼─────────────┐
              │ macOS host   │   │ native peer   │
              │ WebKit SPI   │   │ NativePort    │
              └──────┬───────┘   └──────┬────────┘
                     │                  │
                     ▼                  │
              WebContent process       │
              ┌──────────────────┐      │
              │ Injected Bundle  │      │
              │ Renderer JSC     │      │
              └────────┬─────────┘      │
                       │                │
                       └───── SHM ──────┘
                            │
           ┌────────────────┴────────────────┐
           │ layout / protocol / validation │
           │ ring / flow / channel          │
           │ memory API / signal API        │
           └─────────────────────────────────┘
```

NWIPC의 핵심 가치는 IOSurface나 Injected Bundle 자체가 아니다.

핵심 가치는 다음 경계를 장기적으로 안정화하는 것이다.

```
Stable protocol
Replaceable memory provider
Replaceable signal provider
Replaceable renderer binding
Replaceable WebView integration
Framework-independent native peer
```
